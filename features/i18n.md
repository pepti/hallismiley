EN + IS dictionaries on both sides (`server/i18n` for emails and SSR, `public/js/i18n` for the SPA), the locale middleware and the `locale_choice` cookie, plus the machine-translation helpers that fill `_is`/`_en` sibling columns. `npm run check:i18n` keeps the two dictionaries and every `t('literal')` in sync. Product-specific strings go in `product.<locale>.json` files (product-owned), not here.

**Rules**
- The visitor default (`PUBLIC_DEFAULT_LOCALE`) comes from the identity seam — `identity.locale.publicDefault` in `config/client.json` ('is' here), the env var still winning — on both sides (`server/config/i18n.js`, `public/js/i18n/i18n.js` via `utils/identity.js`); never a literal. `DEFAULT_LOCALE='en'` stays the storage dimension.
- The server tables carry no brand: `t()` injects `{siteName}` (`identity.brand.name`) and `{siteHost}` (APP_URL's host without `www.`) on every call, explicit params win; product wording goes in `product.<locale>.json`, never the engine table (`i18nIdentity.test.js` pins the default text and a downstream brand).
- The page meta is i18n since identity-seam-2: `meta.<key>.title` in both tables, `meta.<key>.description` in the server table; `t()` also injects `{legalName}`, and `has(locale, key)` distinguishes an absent optional string from text. Engine suites take their expected strings from `tests/lib/locale.js` (`tx`, `tClient`, `localePrefix` — the visitor default), never an Icelandic literal.
- A locale lock has two sources and one reader (identity-seam-3): `server/config/i18n.js` `forcedLocaleFor` answers the engine's party lock first, then `identity.routes[*].locale` (prefix-aware, `/` exact, an unsupported locale ignored); `public/js/i18n/i18n.js` mirrors it off the hand-off (`routeLockFor`). Every consumer asks it; a suite builds a locked route's path with `forcedLocaleFor(route) || LC`. `localeLock.test.js` / `localeLockClient.test.js` pin both sides through a temp `client.json` / a stubbed hand-off.
- `t()` inserts a `{param}` value literally on both sides (a replacer function, never a replacement string), so `$&`, `$'` and `$$` in a name or config string are not expanded (ssr-replace-literal; `i18nIdentity.test.js`, `i18nInterpolation.client.test.js`).
- `check:i18n` before pushing translation changes; a missing key fails CI (invariant 10).
- The translator's model calls each take an `aiGate` slot, queued (never refused outright), with the call's timeout starting once the slot is held — `translate()` (request path) waits at most 1 s, tree batches go in waves of `maxConcurrent()` and a BUSY batch gets no per-leaf retry; a batch reply wrapped in prose is salvaged (`parseJsonArray`, icelandicstore #216) and one that still fails logs `stopReason`. The translator still never throws.
- `loadLocale()` dispatches `localechange` for components mounted outside `#app`.
- Full rules: [../docs/ARCHITECTURE.md#5-i18n](../docs/ARCHITECTURE.md#5-i18n).
